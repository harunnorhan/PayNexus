# Documentation

## Use When

Use this skill for:

- README
- project charter
- architecture docs
- component boundaries
- ADRs
- API documentation
- setup guides
- testing guides
- CI/CD documentation
- security documentation
- contribution guides
- release documentation
- portfolio-facing technical documentation

## Goals

- Keep documentation accurate.
- Keep documentation easy to navigate.
- Keep public-facing content professional.
- Make repository setup reproducible.
- Preserve architecture decisions.
- Avoid stale or aspirational documentation.

## Language

All repository documentation must be written in English.

This includes:

- README
- ADRs
- Issues
- Pull Requests
- API docs
- setup docs
- testing docs
- architecture docs
- code comments where needed

The execution guides used by the project owner may be Turkish, but repository content remains English.

Documentation must describe the repository as it actually exists.
